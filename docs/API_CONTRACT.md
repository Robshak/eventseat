# Внутренний контракт реализации

`eventseat.services.Service(db_path: Path, seed: bool = True)` — независимый контекст входа; `close()` освобождает движок. Методы возвращают обычные словари, списки, числа. Даты Python datetime (локальное время). Деньги: int копеек. Ошибки: `eventseat.domain.AppError` с русским сообщением. `PriceChanged(AppError)` означает, что цены корзины обновлены и нужно повторить подтверждение с новым ключом.

`new_context() -> Service` создаёт отдельный неаутентифицированный сервис для той же базы. Список вошедших контекстов хранится только в памяти UI; выход закрывает выбранный контекст, завершение приложения закрывает все.

- `needs_setup() -> bool`; `setup_admin(login, name, password) -> user`; `register(login, name, password) -> user` (не выполняет вход); `login(login,password) -> user`; `logout()`; `current_user -> dict | None` (id, login, name, role).
- `update_profile(name, old_password='', new_password='') -> user`.
- `list_events(search='', category='', date=None, admin=False, *, date_from=None, date_to=None) -> list[event]`: event id,title,description,category,cover_path,duration,published,next_start,min_price. category: кино/концерт/спектакль/лекция/другое. Границы интервала включены, любая может отсутствовать; обратный диапазон вызывает AppError. `date` сохранён для совместимости как однодневный фильтр. `next_start` и `min_price` вычисляются только по будущим доступным сеансам в заданном интервале. `get_event(event_id) -> event`.
- `get_related_event(event_id) -> event`: требует входа и проверяет наличие связанной корзины или бронирования текущего пользователя, включая отменённое; администратору доступно любое событие. Позволяет владельцу открыть описание снятого с публикации мероприятия без разрешения новой покупки. Обычный `get_event` не раскрывает неопубликованные мероприятия посетителю.
- `save_event(title,description,category,duration,published,cover_path='',event_id=None) -> int` (copy uploaded image handled root/UI before call if needed).
- `list_sessions(event_id=None, admin=False, *, hall_id=None, date_from=None, date_to=None, status='all') -> list[session]`: id,event_id,title,hall_id,hall_name,start,duration,status,cancel_reason,free_count,total_count,min_price,category_prices,stage,layout. Статусы фильтра: all/upcoming/completed/cancelled, в записи status — available/cancelled. Интервал относится к дате начала сеанса, обе границы включены. Посетителю в любом случае возвращаются только опубликованные будущие доступные сеансы. `get_session(session_id) -> session`.
- `get_related_session(session_id) -> session`: требует собственную связанную корзину/историю либо роль администратора. Открывает в том числе снятый, отменённый или прошедший сеанс; дополнительно возвращает published,bookable. Администратору bookable всегда False. Доступ к истории не разрешает новое бронирование.
- `save_session(event_id,hall_id,start,*,session_id=None) -> int`; `cancel_session(session_id,reason)`. Новый сеанс копирует цены категорий зала. Редактирование в том же зале сохраняет прежний снимок цен; перенос в другой зал получает цены его категорий. Нельзя изменить event_id сеанса при наличии позиций в корзинах или истории бронирований. Параметры category_prices/seat_prices и метод set_session_prices удалены.
- `list_halls() -> list[hall]`; `get_hall(hall_id) -> hall`: id,name,rows,columns,stage,category_prices,seats. seats: list[{id,row,number,category,enabled}]. row/number: положительные int, category: эконом/стандарт/VIP. `save_hall(name,rows,columns,stage,category_prices,seats=None,hall_id=None) -> int`; seats — полная сетка list[{row,number,category,enabled}], включая проходы с enabled=False. Непустой price_override во входных данных отклоняется AppError. `copy_hall(hall_id,name) -> int`. category_prices — словарь категория → целое число копеек.
- `seat_map(session_id) -> list[seat]`: id,row,number,category,price,status (free/booked/closed). price берётся из сохранённого снимка сеанса, включая стоимость старых мест; price_override не возвращается. `set_seat_closed(session_id,seat_id,closed)` меняет доступность свободного места.
- `add_to_cart(session_id,seat_ids,tariff='standard')`; tariff standard/concession (учебная скидка 20%). `get_cart() -> list[item]`: id,event_id,session_id,seat_id,title,hall_name,start,row,number,category,tariff,price,available. `remove_cart_item(item_id)`; `checkout(request_key: str) -> list[booking]`. Добавление и оформление запрещены администратору. Idempotency key belongs to user; same key returns same result even after success.
- `list_bookings(search='',admin=False,*,event_id=None,hall_id=None,session_id=None,date_from=None,date_to=None,session_status='all',booking_status='all') -> list[booking]`; `get_booking(booking_id) -> booking`; `cancel_booking(booking_id,reason='Отменено пользователем')`. Поиск без учёта регистра по номеру, имени и логину владельца. Фильтры сеанса и бронирования применяются совместно; период относится к текущему началу сеанса. Посетителю возвращаются только его записи. booking id,number,event_id,session_id,user_id,user_name,user_login,title,start,hall_name,status (active/cancelled/completed),cancel_reason,total,tickets (seat_id,row,number,category,tariff,price). Одно бронирование на сеанс при оформлении корзины. После первой брони запрещена смена event_id сеанса, включая случай отмены всех билетов.
- `get_booking_seat_map(booking_id) -> dict`: только владелец или администратор; booking,session,event_id,session_id,hall_id,hall_name,stage,layout,selected_seat_ids,layout_is_partial,published,session_changed. layout — неизменяемый снимок бронирования, включая проходы; кресла содержат seat_id,row,number,category,enabled,selected. session — текущие сведения о сеансе. session_changed означает изменение зала или времени относительно брони. Для старой истории с утраченной исходной геометрией layout_is_partial=True и возвращаются только достоверные места билетов. Нельзя подменять историческую схему текущим шаблоном зала.
- `statistics(session_id=None, *, event_id=None, hall_id=None, date_from=None, date_to=None, session_status='upcoming', booking_status='valid', search='') -> dict`: active_tickets,occupancy_percent,active_amount,total_seats,session_count,booking_count,ticket_count,amount,cancelled_tickets. session_status: all/upcoming/completed/cancelled; booking_status: valid/all/active/completed/cancelled. valid включает неотменённые бронирования, active — только ещё не начавшиеся. Даты относятся к началу сеанса и включают обе границы. booking_count/ticket_count/amount учитывают те же search и booking_status, что list_bookings; заполнение, active_tickets/active_amount рассчитываются по всем неотменённым билетам выбранных сеансов независимо от поиска и статуса брони. cancelled_tickets — число отменённых билетов выбранных сеансов независимо от этих двух фильтров. total_seats включает кресла снимка, в том числе закрытые для продажи, без проходов. Ошибочный интервал/статус вызывает AppError; для пустой выборки счётчики и суммы равны 0. Метод требует администратора. Общая вкладка UI передаёт session_status='all', booking_status='all' по умолчанию, не меняя прежние значения по умолчанию самого метода.

`eventseat.view_state.ViewStates` хранит `AccountViewState` отдельно по user_id: section,routes,drafts,scroll_offsets. `App.set_view(route, capture=None)` запоминает маршрут и обработчик сохранения формы; `capture_view()` собирает простые значения перед уходом; `clear_capture()` снимает обработчик после сохранения. Маршрут содержит section,page и параметры сущности. Пароли, Flet-контролы и сервисы в drafts не сохраняются. Выход забывает состояние аккаунта; закрытие приложения очищает всё. `HallEditor(admin, hall_id=None).show()` использует ключ черновика `hall:<id>` / `hall:new` и сохраняет поля, сетку, выделение и неприменённые свойства правой панели.

`App.open_related(action)` открывает связанную страницу с контекстом возврата. `route['return_to']` содержит сериализуемый источник `{route, drafts, scroll}`; route может содержать следующий источник, drafts — снимок фильтров исходного списка. `restore_route(route)` восстанавливает страницу вместе с её цепочкой. `go_back(fallback)` извлекает один источник либо выполняет fallback; `back_button(default_label, default_action)` создаёт соответствующую кнопку. `AccountViewState.route_key()` не включает return_to. Обновление страницы сохраняет имеющийся источник; переход через боковое меню восстанавливает последний маршрут раздела без добавления профиля в цепочку.

`DateInput(app,label,value='',required=False,...)` — поле даты с маской и календарём. `read()` возвращает date или None и показывает ошибку некорректного значения; внешний обработчик изменения назначается через `on_value_change`, чтобы не заменять внутреннюю маску. Кнопки календаря передают календарный день, а не временную отметку UTC. `App.date_field()` создаёт этот компонент для афиши, расписания и фильтров бронирований.

`TextInput` — общий подкласс Flet TextField для `field()` и базовый класс `DateInput`. Значение из `change.data` синхронизируется до пользовательского `on_change`, в том числе `''`; отсутствие пользовательского обработчика не отключает получение изменений. Пустое значение подтверждается исходящим патчем. Полная очистка поля поэтому доступна форме и сохранению черновика как пустая строка.

`AdminUI.show()` поддерживает четыре вкладки: Мероприятия/Сеансы/Залы/Бронирования. Совместимое название Статистика открывает Бронирования. `session_detail(session_id)` делегирует `session_form(session_id)`; отдельного редактора цен сеанса нет. В `admin:booking_filters` находятся текущие поля, в `admin:booking_applied` — последний успешно применённый запрос для списка и метрик.

В личном списке UI распределяет собственные записи `list_bookings()` по сохранённому `booking.start`: «Предстоящие» строго позже текущего локального datetime, «Прошедшие» — раньше или ровно в этот момент. Статус cancelled не исключает запись ни из списка, ни из счётчика её временной группы. Это разделение не подменяет сервисные фильтры session_status/booking_status административного списка. Выбранная вкладка сохраняется в состоянии текущего аккаунта.

Первичное заполнение — только новая база, не создаёт аккаунтов. База SQLite SQLAlchemy, схема 5, транзакции BEGIN IMMEDIATE для мутаций, частичный UNIQUE для активных мест. Миграция 3 → 4 сохраняет снимок бронирования или явно помечает частичное восстановление старой геометрии. Миграция 4 → 5 очищает price_override только в таблице seats; прежние session_seats, корзины и билеты сохраняют суммы. Предметные классы содержат правила, сервис проверяет права. UI не должен импортировать ORM.
