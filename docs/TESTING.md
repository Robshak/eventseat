# Проверка EventSeat

## Воспроизведение

Из корня репозитория в подготовленном окружении:

```powershell
uv sync --frozen
uv run --frozen pytest -q
uv run --frozen ruff check .
uv run --frozen ruff format --check .
```

Каждый сервисный тест получает временный путь через `pytest.tmp_path`; рабочая база `%LOCALAPPDATA%\EventSeat` не затрагивается. Тест конкурентного подтверждения открывает два независимых SQLAlchemy-движка к одной временной базе и синхронизирует запросы барьером.

## Автоматические сценарии

| Файл | Проверяемые свойства |
|---|---|
| `tests/test_accounts.py` | Однократная настройка администратора, регистрация, неверный пароль, дубли логина, смена профиля и пароля, Argon2id, права сервиса |
| `tests/test_booking.py` | Изоляция корзин и бронирований, отсутствие удержания корзиной, многосеансовое подтверждение, идемпотентность, конфликты, конкурентные движки, изменение цены, скидка, история и отмена |
| `tests/test_schedule_and_halls.py` | Категории и индивидуальные цены, проходы, снимки сеанса, копия зала, пересечение расписания, перенос, защита забронированной схемы, фильтры афиши, статистика |
| `tests/test_storage_guards.py` | Уникальность активного места прямо в SQLite, откат после внедрённой ошибки записи второго билета, прошедшие/отменённые сеансы, завершённые билеты, миграции и защита от понижения версии базы |
| `tests/test_restart.py` | Полный путь от настройки зала и сеанса до билета, сохранение корзины и бронирования после закрытия сервиса, повтор подтверждения после перезапуска, отмена и освобождение места; начальное заполнение без дублей, шесть одновременных первых запусков и восстановление прерванного заполнения |
| `tests/test_domain.py` | Округление скидки, полиморфные билеты, состав и стоимость корзины, проверка владельца при отмене, недопустимые суммы |

Проверка ограничения базы вставляет второй активный билет прямым SQL, обходя сервис, и ожидает `sqlite3.IntegrityError`. Проверка отката создаёт временный SQLite-триггер, принудительно прерывающий запись второго билета, и проверяет отсутствие частичной покупки и сохранение корзины. Временные изменения схемы существуют только в тестовой базе.

## Ручная проверка приложения и Windows-сборки

Проверять нужно реальное окно и отдельно итоговый `dist\release\EventSeat.exe`. Импорт модулей и сервисные тесты не заменяют проверку GUI.

1. Запустить с пустой отдельной папкой `EVENTSEAT_DATA_DIR`; убедиться, что показывается создание первого администратора.
2. Создать администратора, открыть админку, создать зал с проходом, категориями и индивидуальной ценой, проверить предварительный просмотр.
3. Создать и опубликовать мероприятие, загрузить локальную обложку, добавить будущий сеанс с ценами; проверить запрет пересечения расписания.
4. Выйти, зарегистрировать посетителя, найти мероприятие, открыть сеанс и выбрать места. Проверить легенду, цены, обычный и льготный тариф со скидкой 20%.
5. Добавить места в корзину, подтвердить, открыть электронный билет с номером, временем, залом, местами и итогом.
6. Полностью закрыть приложение, запустить снова с той же папкой, войти и проверить сохранённый билет. Отменить его и проверить освобождение места и историю.
7. Проверить админский поиск бронирований, закрытие свободного места, заполнение и сумму активных бронирований, отмену сеанса с отображением причины у посетителя.
8. Повторить запуск готовой сборки с доступными локальными ресурсами и без обращения приложения к интернету; убедиться, что пользовательские файлы находятся в назначенной папке, а не рядом с exe или в папке распаковки.

## Зафиксированные результаты

4 октября 2026 года итоговый прогон перед упаковкой: **82 теста пройдены за 20,73 секунды**. `ruff check .` и `ruff format --check .` прошли для всего проекта (25 файлов Python). Проверена схема версии 3, включая миграцию физической схемы версии 2, конкурентное подтверждение, первый администратор и шесть одновременных первых запусков.

Пробная однофайловая сборка и итоговый `EventSeat.exe` собраны Flet 1.0.3 / PyInstaller 6.22.3 на Python 3.13.5, Windows 11 x64 (22631). Оба приложения фактически запускались как отдельные процессы. Итоговый EXE имеет размер 69 623 015 байт; SHA-256 локальной проверенной сборки: `9308606e487f334ed2ac17ca3d305ba1a15eb02a60e844969e09299a73b40a52`. Сборки Actions могут иметь другую контрольную сумму; для каждого распространяемого EXE прилагается собственный SHA256SUMS.txt.

`.\scripts\verify-build.ps1` выполнил 25 проверок в первом процессе и 6 во втором. В первом процессе обработчики форм создали администратора, зал с проходом и нумерацией с 3-го ряда / 5-го места, цены, опубликованное мероприятие и сеанс. Затем обработчики зарегистрировали посетителя, выбрали кресло, сохранили корзину, подтвердили её и открыли электронный билет. Во втором процессе проверены повторный вход, сохранённый билет, его отмена и освобождение места при сохранении истории.

Получены и визуально проверены снимки работающего Flutter-интерфейса через `ft.Screenshot.capture`; создано 17 PNG. Это проверка действующих обработчиков и фактического рендеринга Windows-клиента, а не симуляция движений мыши. Системный диалог выбора файла не автоматизировался. Во время проверки Python audit hook запрещал все внешние сетевые подключения, разрешая локальное соединение Flet; обложки доступны из ресурсов EXE. Журнал приложения пуст.

Тестовые папки `.qa` не входят в Git. Рабочая база пользователя при проверке не затрагивалась. Отдельный компьютер Windows 10 и ручная проверка всех системных диалогов остаются за пределами выполненного прогона.
