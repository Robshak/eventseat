# Проверка EventSeat

## Воспроизведение

Из корня репозитория в подготовленном окружении:

```powershell
uv sync --frozen
uv run --frozen pytest -q
uv run --frozen ruff check .
uv run --frozen ruff format --check .
```

Каждый сервисный тест получает временный путь через `pytest.tmp_path`; рабочая база `%LOCALAPPDATA%\EventSeat` не затрагивается. Тест конкурентного подтверждения открывает два независимых SQLAlchemy-движка к одной временной базе и синхронизирует запросы барьером.

## Автоматические сценарии

| Файл | Проверяемые свойства |
|---|---|
| `tests/test_accounts.py` | Однократная настройка администратора, регистрация, неверный пароль, дубли логина, смена профиля и пароля, Argon2id, права сервиса |
| `tests/test_booking.py` | Изоляция корзин и бронирований, отсутствие удержания корзиной, многосеансовое подтверждение, идемпотентность, конфликты, конкурентные движки, изменение цены, скидка, история и отмена |
| `tests/test_schedule_and_halls.py` | Категории и индивидуальные цены, проходы, снимки сеанса, копия зала, пересечение расписания, перенос, защита забронированной схемы, фильтры афиши, статистика |
| `tests/test_storage_guards.py` | Уникальность активного места прямо в SQLite, откат после внедрённой ошибки записи второго билета, прошедшие/отменённые сеансы, завершённые билеты, миграции и защита от понижения версии базы |
| `tests/test_restart.py` | Полный путь от настройки зала и сеанса до билета, сохранение корзины и бронирования после закрытия сервиса, повтор подтверждения после перезапуска, отмена и освобождение места; начальное заполнение без дублей, шесть одновременных первых запусков и восстановление прерванного заполнения |
| `tests/test_domain.py` | Округление скидки, полиморфные билеты, состав и стоимость корзины, проверка владельца при отмене, недопустимые суммы |
| `tests/test_ux_services.py` | Интервалы дат с включёнными границами и расчётом цены, независимые контексты входа, запрет бронирования администратору, доступ владельца к снятому событию, сохранность ссылки из истории и корзин |
| `tests/test_account_sessions.py` | Переключение независимых входов и корзин, ошибка/отмена добавления аккаунта, выход из одного или последнего аккаунта, отсутствие дубликата после повторного входа, закрытие всех контекстов |

Проверка ограничения базы вставляет второй активный билет прямым SQL, обходя сервис, и ожидает `sqlite3.IntegrityError`. Проверка отката создаёт временный SQLite-триггер, принудительно прерывающий запись второго билета, и проверяет отсутствие частичной покупки и сохранение корзины. Временные изменения схемы существуют только в тестовой базе.

## Ручная проверка приложения и Windows-сборки

Проверять нужно реальное окно и отдельно итоговый `dist\release\EventSeat.exe`. Импорт модулей и сервисные тесты не заменяют проверку GUI.

1. Запустить с пустой отдельной папкой `EVENTSEAT_DATA_DIR`; убедиться, что показывается создание первого администратора.
2. Создать администратора, открыть админку, создать зал с проходом, категориями и индивидуальной ценой, проверить предварительный просмотр.
3. Создать и опубликовать мероприятие, загрузить локальную обложку, добавить будущий сеанс с ценами; проверить запрет пересечения расписания.
4. Нажать «Добавить аккаунт», зарегистрировать посетителя, найти мероприятие по интервалу дат «С» / «По», открыть сеанс и выбрать места. Проверить календари, включение обеих границ, сброс фильтров, легенду, цены, обычный и льготный тариф со скидкой 20%.
5. Добавить места в корзину, перейти из неё к мероприятию и вернуться. Переключиться на администратора без пароля: личные корзина и бронирования отсутствуют, схема открывается для просмотра. Вернуться к посетителю, убедиться в сохранности корзины, подтвердить, открыть мероприятие и электронный билет из бронирования.
6. Полностью закрыть приложение, запустить снова с той же папкой, войти и проверить сохранённый билет. Отменить его и проверить освобождение места и историю.
7. Проверить админский поиск бронирований, закрытие свободного места, заполнение и сумму активных бронирований, отмену сеанса с отображением причины у посетителя.
8. Повторить запуск готовой сборки с доступными локальными ресурсами и без обращения приложения к интернету; убедиться, что пользовательские файлы находятся в назначенной папке, а не рядом с exe или в папке распаковки.
9. Проверить подсветку кнопок, навигации, карточек и кресел при наведении. Цвет выбранного, занятого или закрытого места должен сохранять свой смысл. Проверить клавиатурный фокус кнопок и полей.
10. Выйти из профиля: аккаунт удаляется из списка слева, другой ранее вошедший аккаунт остаётся доступен. После закрытия процесса все входы требуют пароля заново. Снятое с публикации событие открывается из своей корзины или истории, но недоступно для новой покупки.

## Зафиксированные результаты

4 октября 2026 года, версия 1.1.0: **102 теста пройдены за 30,79 секунды** в скрипте сборки. `ruff check .` и `ruff format --check .` прошли для всего проекта (29 файлов Python). Проверена схема версии 3, включая миграцию физической схемы версии 2, конкурентное подтверждение, первый администратор и шесть одновременных первых запусков. Новые тесты покрывают ограничения администратора, интервалы дат, ссылки из истории и переключение аккаунтов.

Однофайловый `EventSeat.exe` версии 1.1.0 собран Flet 1.0.3 / PyInstaller 6.22.3 на Python 3.13.5, Windows 11 x64 (22631). Локальная сборка сохранена в `dist/v1.1.0`, поскольку прежний EXE в `dist/release` был запущен. Размер нового файла — 69 640 526 байт; SHA-256 локальной проверенной сборки: `67cbaee87294d0a7897c9f3fdf70005a2962117f8a2f207244fd14a68571bbe2`. Сборки Actions могут иметь другую контрольную сумму; для каждого распространяемого EXE прилагается собственный SHA256SUMS.txt.

`.\scripts\verify-build.ps1 -Executable dist/v1.1.0/EventSeat.exe` выполнил 90 проверок в первом процессе и 16 во втором. Обработчики форм создали администратора, зал с проходом и нумерацией с 3-го ряда / 5-го места, мероприятие и сеанс. Проверены роль администратора без покупки, добавление посетителя, оба календаря, интервал и цена карточки, состояния наведения, переходы из корзины и брони. Переключение сохраняет корзину; устаревший обработчик оформления после смены аккаунта игнорируется; выход из профиля удаляет только выбранный вход. Затем оформлен и открыт билет. Во втором процессе проверены отсутствие сохранённых входов, повторная авторизация, сохранённый билет, отмена и освобождение места, переход из отменённой брони и её электронный билет.

Получены снимки работающего Flutter-интерфейса через `ft.Screenshot.capture`; создано 22 PNG. Визуально проверены афиша, поля дат, выделение карточки и места, корзина, бронирования и профиль. Это проверка действующих обработчиков и фактического рендеринга Windows-клиента, а не симуляция движений мыши. Системный диалог выбора файла не автоматизировался. Во время проверки Python audit hook запрещал все внешние сетевые подключения, разрешая локальное соединение Flet; обложки доступны из ресурсов EXE. Журнал приложения пуст.

Тестовые папки `.qa` не входят в Git. Рабочая база пользователя при проверке не затрагивалась. Отдельный компьютер Windows 10 и ручная проверка всех системных диалогов остаются за пределами выполненного прогона.
