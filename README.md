# EventSeat

[Исходный код](https://github.com/Robshak/eventseat) · [Релизы Windows](https://github.com/Robshak/eventseat/releases)

EventSeat — настольная система бронирования мест для Windows 10/11 x64. Приложение работает с локальной SQLite-базой, поддерживает несколько аккаунтов на одном компьютере и полностью русскоязычный интерфейс. Бронирование не является оплатой: платёжная система в проект не входит.

## Возможности

- Афиша опубликованных мероприятий: кино, концерты, спектакли, лекции и другие события; поиск по названию, фильтры по категории и дате.
- Несколько сеансов одного мероприятия, схемы залов с проходами, категориями «эконом», «стандарт», VIP и индивидуальными ценами мест.
- Личная корзина для разных сеансов, подтверждение всей корзины одной транзакцией, электронные билеты и история бронирований.
- Отмена активного бронирования до начала сеанса; отмена сеанса с причиной видна всем владельцам билетов.
- Профиль с изменением имени и пароля; пароли хешируются Argon2id.
- Администрирование мероприятий, публикаций, залов, расписания, цен, закрытых мест и бронирований; статистика активных билетов, заполнения и суммы бронирований.

Обычный билет стоит полную цену места. Льготный тариф даёт **учебную скидку 20%**; подтверждение права на льготу в этой локальной учебной версии не требуется. Суммы хранятся целым числом копеек, скидка округляется до ближайшей копейки по правилу `ROUND_HALF_UP`.

## Первый запуск готовой сборки

Запустите `EventSeat.exe`. Установленные Python и uv получателю сборки не нужны. При первом запуске создайте администратора, задав собственные логин, отображаемое имя и пароль. Встроенного пароля администратора нет. Повторно создать первого администратора после настройки нельзя; обычная регистрация создаёт только пользователей.

Начальные мероприятия, обложки, залы и будущие сеансы создаются один раз для новой базы. Можно сразу ознакомиться с афишей или войти в административную панель и подготовить свои события. Для проверки пользовательского сценария выйдите из аккаунта администратора и зарегистрируйте посетителя.

## Запуск из исходников

Нужны Windows x64, Python **3.13** и `uv`. Зафиксированные зависимости находятся в `pyproject.toml` и `uv.lock`. Первичная установка зависимостей требует доступа к реестру пакетов; обычная работа приложения и готовой сборки выполняется без интернета.

В PowerShell из корня репозитория:

```powershell
uv sync --frozen
uv run --frozen python main.py
```

Или запустите скрипт:

```powershell
.\scripts\run.ps1
```

Если `uv` отсутствует в `PATH`, передайте путь к установленному инструменту:

```powershell
.\scripts\run.ps1 -Uv "C:\путь\к\uv.exe"
```

Виртуальное окружение `.venv` создаётся внутри репозитория. Приложение не зависит от абсолютных путей компьютера разработчика.

## Пользовательские данные и обновление

По умолчанию изменяемые данные находятся в `%LOCALAPPDATA%\EventSeat`:

- `eventseat.db` — аккаунты, залы, расписание, корзины, бронирования и история;
- `covers` — копии загруженных обложек;
- `eventseat.log` и его ротации — журнал ошибок.

SQLite может создавать рядом файлы `eventseat.db-wal` и `eventseat.db-shm`. Данные сохраняются между запусками и при замене exe. Приложение не сохраняет рабочую базу во временной папке распаковки сборки.

Для отдельной тестовой базы можно задать папку перед запуском:

```powershell
$env:EVENTSEAT_DATA_DIR = Join-Path $PWD "qa-data"
uv run --frozen python main.py
```

Переменная действует на процессы, запущенные из этого PowerShell. Для возврата к обычной папке выполните `Remove-Item Env:EVENTSEAT_DATA_DIR`.

Перед обновлением закройте все экземпляры EventSeat и скопируйте папку данных в резервное место. Версия схемы записывается в `PRAGMA user_version`; необходимые миграции запускаются автоматически одной транзакцией. Более новая, чем поддерживает приложение, версия базы вызывает понятную ошибку и не понижается. Подробности миграций приведены в [архитектуре](docs/ARCHITECTURE.md).

## Правила бронирования

Корзина не удерживает место. При подтверждении сервис заново проверяет все позиции: время и статус сеанса, свободные места и цены. Если цена изменилась, корзина обновляется и требуется повторное подтверждение новой суммы. Если хотя бы одна позиция недоступна или сохранение завершается ошибкой, частичных бронирований не остаётся.

Успешная операция создаёт одно бронирование на каждый сеанс корзины, фиксирует стоимость и удаляет оформленные позиции. Повторное подтверждение с тем же ключом возвращает существующий результат. Отмена до начала сеанса освобождает места и сохраняет историю. Изменение цен после подтверждения не изменяет стоимость билета.

Действующие сеансы одного зала не могут пересекаться. При активных бронированиях запрещено менять зал и время сеанса, а также разрушать используемую схему зала. Для новой схемы создайте копию зала; для переноса забронированного сеанса отмените старый с объяснением и создайте новый.

## Тесты и проверки

```powershell
uv run --frozen pytest -q
uv run --frozen ruff check .
uv run --frozen ruff format --check .
```

Тесты используют отдельные временные базы. Покрытие сценариев и результаты конкретных проверок приведены в [docs/TESTING.md](docs/TESTING.md). [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) объясняет разделение слоёв и применение ООП на собственных классах проекта.

## Сборка Windows

Сборку выполняйте на Windows x64 с Python 3.13:

```powershell
.\scripts\build.ps1
```

Скрипт устанавливает зависимости по lock-файлу, проверяет Ruff, форматирование и pytest, затем вызывает `flet pack` с PyInstaller, иконкой и локальными ресурсами. Ожидаемый результат — `dist\release\EventSeat.exe`; в конце выводится SHA-256. Полученный файл нужно проверять фактическим запуском, включая повторный запуск с сохранённой базой. Тестовый протокол хранится в [docs/TESTING.md](docs/TESTING.md).

`.venv`, базы пользователей, журналы, кэши, `build` и `dist` не входят в исходный код. Готовую сборку следует публиковать как вложение релиза, соответствующего версии исходников.

После сборки запустите `.\scripts\verify-build.ps1`: он создаёт отдельную случайную папку в `.qa`, проверяет готовый EXE в двух процессах, сохраняет PNG и JSON-отчёты. Проверка использует обработчики действующего интерфейса и снимки, возвращённые настольным клиентом Flet. Тестовый пароль существует только в окружении процессов и не записывается в файлы. Внешние Python-соединения запрещены во время проверки; локальное соединение Flet разрешено.

Workflow Windows повторяет сборку и проверку, а после успешного push в `main` публикует версию `v1.0.0` один раз. Существующий релиз и его вложения автоматически не перезаписываются. Клиент Flet распаковывается в пользовательский кэш `%USERPROFILE%\.flet\client`; это не каталог рабочих данных EventSeat.

## Ограничения версии 1.0

Приложение рассчитано на локальную базу одного компьютера. Сервер, синхронизация между компьютерами, реальные платежи и удержание мест по таймеру отсутствуют. Все даты трактуются в локальном времени компьютера. Хранение базы в сетевой или синхронизируемой папке не является поддерживаемым многопользовательским режимом.

Электронный билет доступен внутри приложения. PDF-экспорт, QR-коды, контроль прохода, промокоды, избранное и интернет-уведомления оставлены для будущих версий. Конструктор использует сетку до 50 рядов и 50 ячеек в ряду. Расчёт заполнения и суммы относится к активным бронированиям и не учитывает платежи.
