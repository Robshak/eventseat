# EventSeat

[Исходный код](https://github.com/Robshak/eventseat) · [Релизы Windows](https://github.com/Robshak/eventseat/releases)

EventSeat — настольная система бронирования мест для Windows 10/11 x64. Приложение работает с локальной SQLite-базой, поддерживает несколько аккаунтов на одном компьютере и полностью русскоязычный интерфейс. Бронирование не является оплатой: платёжная система в проект не входит.

## Возможности

- Афиша опубликованных мероприятий: кино, концерты, спектакли, лекции и другие события; поиск по названию, фильтры по категории и интервалу дат «С» / «По». Календарь выбирает день без смещения из-за часового пояса; ручной ввод добавляет точки, поддерживает исправления и показывает ошибки. Обе границы включены; дата и цена карточки относятся к найденному интервалу.
- Несколько сеансов одного мероприятия, схемы залов с проходами и категориями «эконом», «стандарт», VIP. Цены задаются только для категорий в зале. В конструкторе схема подстраивается под доступную ширину, свойства открываются рядом или ниже в узком окне; Shift выделяет прямоугольник, Ctrl добавляет или убирает отдельное место. Группе можно назначить категорию или превратить её в проход. Нажатие вне схемы и свойств снимает выделение; сохранение и предпросмотр доступны в заголовке.
- Личная корзина для разных сеансов, подтверждение всей корзины одной транзакцией, электронные билеты и история бронирований. «Мои бронирования» разделены на «Предстоящие» и «Прошедшие» со счётчиками; принадлежность определяется датой и временем начала, включая отменённые заказы. Из билета доступны мероприятие, конкретный сеанс и схема с отмеченными местами по сохранённому снимку бронирования.
- Отмена активного бронирования до начала сеанса; отмена сеанса с причиной видна всем владельцам билетов.
- Профиль с изменением имени и пароля; пароли хешируются Argon2id.
- Текстовые поля принимают полную очистку: удаление последнего символа передаёт пустое значение форме, поиску и черновику. Поля дат используют тот же механизм очистки вместе со своей маской.
- Клиентский фильтр даты допускает пустую строку: можно удалить одиночный `0` или всю дату до пустого поля, не возвращая последний символ.
- Переключение между аккаунтами, в которые вошли в текущем запуске, через меню слева. Широкое меню открывается вверх поверх содержимого, показывает имя, логин и роль, прокручивает длинный список и закрывается по Esc или нажатию снаружи. «Добавить аккаунт» открывает вход или регистрацию; выход находится в профиле.
- Четыре административные вкладки: «Мероприятия», «Сеансы», «Залы», «Бронирования». Карточка мероприятия открывает его сеансы, карточка сеанса сразу открывает редактор даты, времени, события и зала. Цены редактируются в зале; в форме сеанса есть прямые переходы к мероприятию и залу.
- Переход из афиши к управлению конкретным сеансом прокручивает список к нему и выделяет нужную карточку.
- На вкладке «Бронирования» метрики и список используют общие фильтры по мероприятию, залу, сеансу, периоду, статусам и номеру/владельцу брони. Компактные карточки переносят номер, статус и сумму при недостатке ширины; здесь же доступны билеты, схемы мест и отмена бронирования.
- Страницы запоминают открытую вкладку, положение прокрутки и незавершённые формы для каждого аккаунта в текущем запуске. Наведение выделяет элементы без изменения размеров; список аккаунтов имеет контрастные подписи и рамку.
- Возврат ведёт на страницу, с которой открыт текущий экран. Например, после перехода из создания сеанса в зал можно вернуться в ту же форму с введёнными датой и временем. Цепочка возвратов сохраняется после профиля и переключения аккаунтов; вложенные списки восстанавливают исходные фильтры и прокрутку.

Обычный билет стоит полную цену места. Льготный тариф даёт **учебную скидку 20%**; подтверждение права на льготу в этой локальной учебной версии не требуется. Суммы хранятся целым числом копеек, скидка округляется до ближайшей копейки по правилу `ROUND_HALF_UP`.

## Первый запуск готовой сборки

Запустите `EventSeat.exe`. Установленные Python и uv получателю сборки не нужны. При первом запуске создайте администратора, задав собственные логин, отображаемое имя и пароль. Встроенного пароля администратора нет. Повторно создать первого администратора после настройки нельзя; обычная регистрация создаёт только пользователей.

Начальные мероприятия, обложки, залы и будущие сеансы создаются один раз для новой базы. Можно сразу ознакомиться с афишей или войти в административную панель и подготовить свои события. Администратор управляет событиями и просматривает схемы; бронировать может только посетитель. Для проверки пользовательского сценария нажмите «Добавить аккаунт» слева и зарегистрируйте посетителя. После этого между двумя аккаунтами можно переключаться без повторного ввода пароля до закрытия приложения.

Переключение сохраняет вход, а «Выйти из аккаунта» в профиле удаляет текущий аккаунт из списка. Пароли и список входов не сохраняются на диск: после перезапуска нужно войти заново. Корзины, билеты и профили сохраняются в базе независимо от переключения и выхода.

Незавершённые формы, фильтры и выбранные вкладки сохраняются отдельно для каждого вошедшего аккаунта только в памяти процесса. Можно перейти из конструктора зала в профиль и вернуться к своему черновику. Выход из аккаунта очищает его черновики, закрытие приложения — все черновики. Поля паролей не входят в это состояние и после ухода со страницы заполняются заново.

## Запуск из исходников

Нужны Windows x64, Python **3.13** и `uv`. Зафиксированные зависимости находятся в `pyproject.toml` и `uv.lock`. Первичная установка зависимостей требует доступа к реестру пакетов; обычная работа приложения и готовой сборки выполняется без интернета.

В PowerShell из корня репозитория:

```powershell
uv sync --frozen
uv run --frozen python main.py
```

Или запустите скрипт:

```powershell
.\scripts\run.ps1
```

Если `uv` отсутствует в `PATH`, передайте путь к установленному инструменту:

```powershell
.\scripts\run.ps1 -Uv "C:\путь\к\uv.exe"
```

Виртуальное окружение `.venv` создаётся внутри репозитория. Приложение не зависит от абсолютных путей компьютера разработчика.

## Пользовательские данные и обновление

По умолчанию изменяемые данные находятся в `%LOCALAPPDATA%\EventSeat`:

- `eventseat.db` — аккаунты, залы, расписание, корзины, бронирования и история;
- `covers` — копии загруженных обложек;
- `eventseat.log` и его ротации — журнал ошибок.

SQLite может создавать рядом файлы `eventseat.db-wal` и `eventseat.db-shm`. Данные сохраняются между запусками и при замене exe. Приложение не сохраняет рабочую базу во временной папке распаковки сборки.

Для отдельной тестовой базы можно задать папку перед запуском:

```powershell
$env:EVENTSEAT_DATA_DIR = Join-Path $PWD "qa-data"
uv run --frozen python main.py
```

Переменная действует на процессы, запущенные из этого PowerShell. Для возврата к обычной папке выполните `Remove-Item Env:EVENTSEAT_DATA_DIR`.

Перед обновлением закройте все экземпляры EventSeat и скопируйте папку данных в резервное место. Версия схемы записывается в `PRAGMA user_version`; необходимые миграции запускаются автоматически одной транзакцией. Более новая, чем поддерживает приложение, версия базы вызывает понятную ошибку и не понижается. Подробности миграций приведены в [архитектуре](docs/ARCHITECTURE.md).

## Правила бронирования

Корзина не удерживает место. При подтверждении сервис заново проверяет все позиции: время и статус сеанса, свободные места и цены. Если цена изменилась, корзина обновляется и требуется повторное подтверждение новой суммы. Если хотя бы одна позиция недоступна или сохранение завершается ошибкой, частичных бронирований не остаётся.

Успешная операция создаёт одно бронирование на каждый сеанс корзины, фиксирует стоимость и удаляет оформленные позиции. Повторное подтверждение с тем же ключом возвращает существующий результат. Отмена до начала сеанса освобождает места и сохраняет историю. Изменение цен после подтверждения не изменяет стоимость билета.

Действующие сеансы одного зала не могут пересекаться. При активных бронированиях запрещено менять зал и время сеанса, а также разрушать используемую схему зала. Для новой схемы создайте копию зала; для переноса забронированного сеанса отмените старый с объяснением и создайте новый.

Если сеанс уже находится в корзинах или имеет историю бронирований, его нельзя переназначить другому мероприятию: ссылки должны вести к исходному событию. Если событие снято с публикации, владелец корзины или брони может открыть его описание, но покупка недоступна; электронный билет и история продолжают открываться.

Новые бронирования сохраняют собственную схему зала: перенос отменённого сеанса и изменение шаблона не меняют места в историческом билете. При обновлении старой базы схема билетов восстанавливается из имеющихся снимков. Если исходная геометрия уже утрачена, показываются только достоверные места из билета с пометкой о неполной схеме.

Версия 1.3 использует цены категорий зала для новых сеансов. Изменение этих цен не пересчитывает существующий сеанс; перенос в другой зал получает цены его категорий. Миграция схемы 4 → 5 убирает индивидуальные цены только из шаблонов залов. Старые цены мест в сеансах, суммы корзин и стоимость оформленных билетов сохраняются.

## Тесты и проверки

```powershell
uv run --frozen pytest -q
uv run --frozen ruff check .
uv run --frozen ruff format --check .
```

Тесты используют отдельные временные базы. Покрытие сценариев и результаты конкретных проверок приведены в [docs/TESTING.md](docs/TESTING.md). [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) объясняет разделение слоёв и применение ООП на собственных классах проекта.

## Сборка Windows

Сборку выполняйте на Windows x64 с Python 3.13:

```powershell
.\scripts\build.ps1
```

Скрипт устанавливает зависимости по lock-файлу, проверяет Ruff, форматирование и pytest, затем вызывает `flet pack` с PyInstaller, иконкой и локальными ресурсами. Ожидаемый результат — `dist\release\EventSeat.exe`; в конце выводится SHA-256. Полученный файл нужно проверять фактическим запуском, включая повторный запуск с сохранённой базой. Тестовый протокол хранится в [docs/TESTING.md](docs/TESTING.md).

Чтобы сохранить новый EXE отдельно, например пока предыдущая сборка открыта:

```powershell
.\scripts\build.ps1 -OutputDirectory "dist/v1.4.1"
.\scripts\verify-build.ps1 -Executable "dist/v1.4.1/EventSeat.exe"
```

`SHA256SUMS.txt` создаётся в выбранной папке рядом с EXE. Параметр не меняет папку пользовательских данных.

`.venv`, базы пользователей, журналы, кэши, `build` и `dist` не входят в исходный код. Готовую сборку следует публиковать как вложение релиза, соответствующего версии исходников.

После сборки запустите `.\scripts\verify-build.ps1`: он создаёт отдельную случайную папку в `.qa`, проверяет готовый EXE в двух процессах, сохраняет PNG и JSON-отчёты. Проверка использует обработчики действующего интерфейса и снимки, возвращённые настольным клиентом Flet. Тестовый пароль существует только в окружении процессов и не записывается в файлы. Внешние Python-соединения запрещены во время проверки; локальное соединение Flet разрешено.

Workflow Windows повторяет сборку и проверку, а после успешного push в `main` публикует версию из `pyproject.toml` один раз. Существующий релиз и его вложения автоматически не перезаписываются. Клиент Flet распаковывается в пользовательский кэш `%USERPROFILE%\.flet\client`; это не каталог рабочих данных EventSeat.

## Ограничения версии 1.4.1

Приложение рассчитано на локальную базу одного компьютера. Сервер, синхронизация между компьютерами, реальные платежи и удержание мест по таймеру отсутствуют. Все даты трактуются в локальном времени компьютера. Хранение базы в сетевой или синхронизируемой папке не является поддерживаемым многопользовательским режимом.

Электронный билет и его схема доступны внутри приложения. PDF-экспорт, QR-коды, контроль прохода, промокоды, избранное и интернет-уведомления оставлены для будущих версий. Конструктор использует сетку до 50 рядов и 50 ячеек в ряду.

На общей вкладке бронирований период относится к дате начала сеанса, обе границы включены. Поиск по номеру/владельцу и состояние брони одновременно меняют список, количество и сумму. Заполнение рассчитывается по всем неотменённым билетам выбранных сеансов; поиск и состояние брони его не меняют. По умолчанию вкладка показывает все состояния сеансов и бронирований. Суммы не учитывают платежи и не являются выручкой.
